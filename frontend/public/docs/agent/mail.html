Mail

Inbound email hosted by Muse Proxy. No IMAP, no SMTP, no outbound sending.

Reading this as an agent? Load /api/agent with your key first. It reports the Mail connection id and every mailbox your key can reach, with the effective access level. Read /llms.txt for the shared conventions.

Authentication

Authorization: Bearer muse_...

Mail is one service in the same gateway as CalDAV. Your key is account-bound and carries grants. Never put it in a query string.

What a mailbox is

The account owner has one Mail connection. Each mailbox is a resource on it, keyed by its lowercased address. That means access is the same intersection as everywhere else:

LayerSet byValues
Mailbox ceilingThe account owner, on the mailbox pagenone, read, write
Key grantThe account owner, per keyone mailbox address, or * for every mailbox

A mailbox starts at none. A key with a matching grant still gets nothing until the owner raises the ceiling. A denial is a 403 with required, effective, resource and permittedResources; read it instead of retrying.

A key with no grant on the Mail connection cannot even address it. The catalog shows the connection id:

curl -sS -H "Authorization: Bearer $MUSE_KEY" "$MUSE_URL/api/agent"

Endpoints

All paths are relative to /api/agent/mail/<connectionId>. Percent-encode the @ in an address as %40.

Creating, configuring and deleting mailboxes, and minting keys, are owner-only console actions. They are deliberately not exposed to agent keys.

Reading mail

curl -sS \
  -H "Authorization: Bearer $MUSE_KEY" \
  "$MUSE_URL/api/agent/mail/$CONNECTION/mailboxes/notes%40mail.example.com/messages?limit=20&unread=true"

List query parameters: limit 1–200 (default 50), cursor, order=asc|desc, since, before, unread, starred, hasAttachments, and q (case-insensitive substring over subject, sender, preview and text). Follow nextCursor while hasMore is true.

curl -sS \
  -H "Authorization: Bearer $MUSE_KEY" \
  "$MUSE_URL/api/agent/mail/$CONNECTION/messages/$MESSAGE_ID"

Detail responses add text, html, bodyTruncated, headers, and attachments with a url you can fetch with the same key. HTML is untrusted. Never render it into a page; sanitize it or use the text part.

Cleanup

POST /mailboxes/{address}/trim enforces the mailbox quotas now and returns withinQuota. It deletes up to 2,000 messages per call; call it again if the mailbox is still above quota.

POST /mailboxes/{address}/purge accepts exactly one selector:

{"all": true}
{"olderThanDays": 30}
{"before": "2026-01-01T00:00:00Z"}

One call deletes up to 5,000 messages and returns remaining and hasMore; repeat while hasMore is true. retention_days is stored for future use; no cron deletes mail automatically.

Storage and limits

LimitValue
Cloudflare inbound message25 MiB
MAX_MESSAGE_BYTES (default)10 MiB
Attachments in D1at or below INLINE_ATTACHMENT_MAX (1 MiB default)
Attachments in KVabove that, up to 25 MiB each
Text and HTML partsMAX_BODY_BYTES each (512 KiB default)
Raw RFC 822 sourcekept only at or below RAW_INLINE_MAX (128 KiB default)

rawAvailable is false for large messages; check it before requesting /raw. An attachment with storage: "unavailable" could not be stored and has no content.

Delivery

Cloudflare Email Routing delivers an address to the Worker only when a rule for it exists. The Worker checks the mailbox row and rejects unknown or disabled addresses with a permanent SMTP failure. Messages above MAX_MESSAGE_BYTES are rejected. Duplicate deliveries with the same source hash are ignored.

A mailbox whose overflow is trim_oldest deletes its oldest mail after accepting a new message. reject_new throws instead, so the sender may retry; storage is not guaranteed to be retried by every sender.

Errors

{
  "ok": false,
  "apiVersion": "2026-09-13",
  "error": {
    "code": "insufficient_access",
    "message": "This key has read access to 'notes@mail.example.com' but write is required.",
    "details": {
      "required": "write",
      "effective": "read",
      "resource": "notes@mail.example.com",
      "permittedResources": ["notes@mail.example.com"]
    }
  }
}

Successful responses use {"ok":true,"apiVersion":"...","data":{...}}. Every response carries X-Muse-Api-Version and the pending-notice headers.
